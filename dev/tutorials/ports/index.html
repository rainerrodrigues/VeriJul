Ports and wide signals

Every top-level port of a DUT is a property. Inputs can be read and written; outputs can only be read.

Types

Reads return the smallest unsigned type that holds the port, which is also how Verilator stores it:

Port widthJulia type
1–8 bitsUInt8
9–16 bitsUInt16
17–32 bitsUInt32
33–64 bitsUInt64
over 64 bitsBigInt
using VeriJul

dir = joinpath(pkgdir(VeriJul), "examples", "counter")
dut = load_dut([joinpath(dir, "counter.v"), joinpath(dir, "inverter.v")], "counter";
               include_dirs=[joinpath(dir, "include")], build_dir=mktempdir())
settle!(dut)
(typeof(dut.step), typeof(dut.slow_count), typeof(dut.upper), typeof(dut.wide_out))
(UInt8, UInt16, UInt64, BigInt)

Writing values

Writes accept any Integer, including Bool, and are truncated to the port width like a Verilog assignment. Negative numbers are stored as two's complement:

dut.step = 300          # 8-bit port: 300 & 0xff
a = dut.step
dut.step = -1
b = dut.step
dut.step = true
c = dut.step
(a, b, c)
(0x2c, 0xff, 0x01)

Writing an output, an unknown port or a non-integer is an error:

try
    dut.count = 1
catch err
    err
end
ErrorException("Port `count` is an output and cannot be written")

Ports wider than 64 bits

Wide ports read back as BigInt and accept any integer. wide_out is the bitwise inverse of the 100-bit wide_in, and upper is its top 64 bits:

x = big(2)^99 + big(2)^64 + 0xCAFE
dut.wide_in = x
settle!(dut)
(wide_out = string(dut.wide_out, base=16),
 expected = string((big(2)^100 - 1) ⊻ x, base=16),
 upper = dut.upper)
(wide_out = "7fffffffeffffffffffff3501", expected = "7fffffffeffffffffffff3501", upper = 0x8000000010000000)

Under the hood a wide port is an array of 32-bit words, lowest word first. Bit i of the value is bit i of the port.

Setting inputs and reading outputs in time

Setting an input doesn't evaluate the design. The new value takes effect at the next clock edge (when the simulator evaluates the model) or when you call settle!. Reading an output right after @tick returns gives its value just after that edge.

Lower-level access

build_dut returns the library path and a generated bindings.jl with one function per port (set_<port>!, get_<port>) operating on a VerilatedModel. See Lower-level API.
