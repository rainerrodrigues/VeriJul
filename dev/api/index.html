API

Loading designs

VeriJul.Device.load_dut — Function
load_dut(sources, top_module; kwargs...) -> DUT

Builds the design (or reuses a cached build) and loads it. Takes the same keywords as build_dut: build_dir, include_dirs, defines, parameters, verilator_args, force, verbose.

dut = load_dut("filter.v", "filter")
dut.in_data = 0xFF

By default the build goes into VeriJul's build cache, one folder per design and set of options, so nothing is written to the current directory.

source
VeriJul.Device.DUT — Type
DUT

A loaded hardware design. Read and write its ports as properties:

dut.in_data = 0x42      # set an input (truncated to the port width)
dut.out_data            # read an output (or an input)

Ports up to 64 bits read back as UInt8/UInt16/UInt32/UInt64; wider ports read back as BigInt and accept any Integer.

Create one with load_dut. List its ports with ports.

source
VeriJul.Device.ports — Function
ports(dut) -> Vector{HardwarePort}

The design's top-level ports, in declaration order.

VeriJul.Interop.settle! — Function
settle!(model)

Evaluates the model without writing a waveform sample, so combinational outputs reflect inputs you just set. Useful for designs without a clock.

source
VeriJul.Interop.enable_trace! — Function
enable_trace!(model, filename)

Starts writing a VCD waveform to filename. The file is flushed and closed by destroy!.

source
VeriJul.Interop.destroy! — Function
destroy!(model)

Frees the C++ model, closes its VCD file and unloads the library. Safe to call more than once. Stop any running clock with stop_clock! first.

Simulation

VeriJul.SimCore.Simulator — Type
Simulator(dut; clock=:clk, half_period=5)

Simulation state for a DUT (or a bare VerilatedModel): the current time and the clocks that drive it.

clock names the main clock input; tick and @tick wait on it unless told otherwise. Add more clocks with add_clock!.

sim.time is the simulation time of the most recent clock edge.

source
VeriJul.SimCore.add_clock! — Function
add_clock!(sim, name; half_period=5, phase=0)

Adds another 1-bit clock input. It toggles every half_period time units. All clocks run on the same timeline, so their edges interleave correctly. Wait for its edges with tick(sim; clock=name).

phase is measured from the current simulation time: before the simulation has started, the first toggle is at time phase; if clocks are added to a stopped simulation, the first toggle is phase after sim.time (or one half_period after it when phase is 0), so time never goes backwards. The simulator must not be running.

source
VeriJul.SimCore.start_clock! — Function
start_clock!(sim[, half_period]) -> Task

Starts the clocks in a background task. On each step it toggles the clocks due at the earliest time, evaluates the design (writing a waveform sample if tracing is on) and wakes tasks waiting in tick.

Passing half_period changes the main clock's half period. Throws if the clock is already running.

source
VeriJul.SimCore.stop_clock! — Function
stop_clock!(sim)

Stops the clocks and waits for the background task to finish. Tasks still waiting in tick get a ClockStopped error instead of hanging. Call this before destroy!-ing the design.

source
VeriJul.SimCore.tick — Function
tick(sim, n=1; clock=nothing, edge=:rising, timeout=nothing)

Waits for n edges of a clock (the main clock unless clock is given). edge is :rising or :falling. timeout is a wall-clock limit in seconds; when it passes, a TickTimeout is thrown.

Throws ClockStopped if the clock isn't running. @tick is shorthand for this.

source
VeriJul.DSL.@tick — Macro
@tick sim
@tick sim n
@tick sim n clock=:clk_b edge=:falling timeout=1.0

Waits for the next rising edge of the main clock, or n edges. Keywords are passed to tick: clock, edge and timeout (wall-clock seconds).

source
VeriJul.SimCore.reset! — Function
reset!(sim, port=:rst; cycles=2, active_high=true)

Asserts a reset input for cycles rising edges of the main clock, then releases it. The clock must be running. Use active_high=false for an active-low reset such as rst_n.

source
VeriJul.DSL.@testbench — Macro
@testbench func

Defines func as usual and also a launch_<func>(sim::Simulator) that runs it as an asynchronous task, so it can wait on clock edges with @tick.

@testbench function drive(sim)
    sim.dut.in_data = 0xFF
    @tick sim
end

task = launch_drive(sim)
wait(task)

Building

VeriJul.Builder.build_dut — Function
build_dut(sources, top_module; kwargs...) -> (lib_path, bindings_path)

Verilates sources (one path or a vector of paths) with top_module as the top, generates bindings and compiles everything into a shared library. Returns the library path and the path of the generated bindings.jl.

Most code should call load_dut, which builds and loads in one step and takes the same keywords.

Keywords

  • build_dir: where build files go. By default each design and set of options gets its own folder in VeriJul's build cache (a Scratch.jl space, removed with clear_build_cache or when VeriJul is uninstalled). A directory you pass must be empty, new, or one VeriJul created earlier; VeriJul never deletes files it didn't create.
  • include_dirs=String[]: directories searched by $`include$ (-I).
  • defines=Dict(): preprocessor macros, e.g. Dict("DEPTH" => 16, "FAST" => nothing) (+define+).
  • parameters=Dict(): top-level parameter overrides, e.g. Dict("WIDTH" => 12) (-G). Values are passed to Verilator as written, so string parameters need their own quotes: "\"name\"".
  • verilator_args=String[]: extra command-line arguments for Verilator.
  • force=false: rebuild even if nothing changed.
  • verbose=false: show Verilator and compiler output.

Builds are cached: if the sources, files in include_dirs, options, Verilator version and compiler are unchanged, the existing library is reused. To rebuild, VeriJul empties the build directory first. Files pulled in by $`include$ from outside include_dirs are not tracked; pass force=true after changing them.

Set the CXX environment variable to choose the C++ compiler (default g++, or c++ on macOS; CXX="ccache g++" also works). Set VERIJUL_VERILATOR to choose the Verilator executable (see verilator_cmd).

source
VeriJul.Builder.clear_build_cache — Function
clear_build_cache()

Deletes all cached builds in VeriJul's default build location (used when build_dir is not given). Designs that are still loaded keep working.

source
VeriJul.Builder.verilator_cmd — Function
verilator_cmd() -> Cmd

The Verilator command VeriJul runs. Set the VERIJUL_VERILATOR environment variable to the path of a verilator executable to use that one; otherwise verilator is looked up on PATH. Throws an error explaining how to install Verilator if none is found.

source
VeriJul.Builder.verilator_version — Function
verilator_version() -> VersionNumber

Returns the version of the Verilator that verilator_cmd finds, or throws an error explaining how to install it.

source
VeriJul.Builder.HardwarePort — Type
HardwarePort(name, direction, width)

A top-level port of a Verilated design. direction is :in or :out (inout ports are treated as :in), width is the bit width.

source

extract_ports(header_path) -> Vector{HardwarePort}

Reads the ports of a Verilated model from its generated V<top>.h header.

VeriJul.Builder.generate_bindings — Function
generate_bindings(ports, module_name) -> (cpp_code, jl_code)

Generates the C++ shim exposing the model through a C ABI, and the Julia AutoBindings module that wraps it (set_<port>! / get_<port>). Every port gets a getter; input ports also get a setter.

Low-level model access

VeriJul.Interop.VerilatedModel — Type
VerilatedModel(lib_path, create_sym=:top_create)

Loads a shared library built by build_dut and instantiates the model. The model is freed automatically when garbage-collected, or explicitly with destroy!.

Most code should use load_dut instead, which returns a DUT with named port access.

source
VeriJul.Interop.eval_step! — Function
eval_step!(model, time)

Evaluates the model and, if tracing is enabled, dumps a waveform sample at time. The simulator's clock calls this for you on every clock edge.
